# Personalized headshot generation

## Prompt
Design a system where a user uploads several photos of their face and receives professional headshots that preserve their identity.

## Functional requirements
- Input: 10-20 images of the user from different angles and poses.
- Output: diverse, high-quality professional headshots preserving identity.
- No user prompts: the system uses hand-engineered prompts.

## Non-functional requirements
- Training time per user acceptable (about 15 minutes with DreamBooth); personalized models need not be stored after generation (details beyond that not captured).

## Estimations
DreamBooth about 15 min finetune per subject; stored per-subject model would take GBs; LoRA a few MB.

## API
Not covered in the source.

## Data model
User images resized to uniform dimensions, augmented (mirroring, slight rotation, scaling), tagged "An image of a [V] person"; mixed with generic face images generated by the pretrained model for prior preservation.

## Architecture (high-level design)
Data pipeline (user upload prep, generic images), training pipeline (per-user DreamBooth finetune of a pretrained 1024x1024 U-Net text-to-image model), inference pipeline (hand-engineered prompts such as "A professional headshot of [V] wearing a business suit", one image per prompt, CFG sampling).

## Deep dives
- Tuning-free vs tuning-based personalization; textual inversion vs DreamBooth vs LoRA; DreamBooth chosen for identity preservation, acceptable training time and no storage need.
- Rare-token identifier selection (not common words, not random characters).
- Loss: alpha x subject reconstruction + beta x class-specific prior preservation.
- Evaluation: text alignment (CLIPScore), FID, image alignment (CLIP, DINO/DINOv2, facial similarity); online metrics include user satisfaction, conversion to paid, engagement.

## Trade-offs and decisions
DreamBooth (quality) vs LoRA (cost/storage) vs tuning-free (speed, single image).
